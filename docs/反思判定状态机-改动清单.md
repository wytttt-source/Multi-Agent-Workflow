# 反思判定状态机 + 改动清单

> **版本**：v1（2026-11-05）
> **适用代码基线**：`15cb3c6`（工作区未提交改动之上）
> **数据基线**：`data/runs/*.json` 共 **20** 份运行记录
> **文档定位**：把"反思节点如何判定、判定后如何重规划"写成可直接对照代码的可复现规格，并给出缺陷清单（ID / 位置 / 改法 / 验收）。本文档只描述"应该怎样"，不含实现；实现与验收见第 7、9 节。

---

## 0. 为什么需要这份文档

1. 论文主线的实验变量是**反思判定**，若判定规则本身散落在 `nodes.py` 的多个 `if` 里、且优先级未写明，实验结论无法复现，也无法解释"某一轮为什么被判成 `分解不合理`"。
2. `reflection.verdict` 已按 6 类落盘，但**"通过"这一类的口径偏松**（见 4.1），会直接污染论文最关键的分母：合格样本数。
3. 20 份历史记录中 `gated_by=gate` 与 `coverage_rule` **各 0 次触发**，必须解释清楚"是门控够严，还是门控看不见"，否则审稿人会质疑门控是否只是装饰。

## 1. 状态定义（6 个终态）

| 终态 | 含义 | 计入合格样本 | 当前产生位置（`agents/nodes.py`） |
|---|---|---|---|
| `通过` | 有证据 + 有来源 + 内容达标 | ✅ 是 | L269-311 门控后、L333 规则兜底、L399 自由反思 |
| `降级通过` | 回答可读，但**无外部证据支撑**（缺资料且已声明） | ❌ 否 | L296-299、L326-331、L399 |
| `内容不合格` | 偏题 / 过短 / 编造来源 | ❌ 否 | L300-307、L317-321 |
| `分解不合理` | 复合主题的证据未覆盖全部比较对象 | ❌ 否 | L229-233、L251-255 |
| `检索失败` | 检索层返回 0 条证据 | ❌ 否 | 由裁判 LLM 判定，随即转 `证据不足` |
| `系统繁忙` | 生成/裁判侧 LLM 不可用 | ❌ 否 | L151-153、L179-188 |

**硬约束**

- `降级通过` 必须与 `通过` 分开统计（"缺资料"本身是合理结论，不等于系统失败，但**不能**算合格样本）。
- 任意终态都要在 `run_stats.reflection` 中同时写明 `verdict` 与 `gated_by`，缺一不可。

## 2. 状态机

### 2.1 状态转移图

```text
                   ┌──────────┐   replan_global
        topic ────▶│ planner  │◀──────────────┐
                   └────┬─────┘               │
                        ▼                     │
                   ┌──────────┐  replan_local │
                   │ executor │◀──────────────┼──────┐
                   └────┬─────┘               │      │
                        ▼                     │      │
                   ┌────────────┐             │      │
                   │ reflection │─────────────┘      │
                   └────┬───────┘  (内容不合格/分解不合理/系统繁忙)
        ┌───────────────┼────────────────┬──────────────┐
        ▼               ▼                ▼              ▼
     [通过]        [降级通过]      [证据不足]      直接 END
        │               │                │      (replan≥3 / llm_fail≥3)
       END             END               ▼
                                   ┌────────────────┐
                                   │ free_reflection│──▶ END
                                   └────────────────┘  (通过 / 降级通过)
```

### 2.2 反思节点判定表（**按代码实际执行顺序，顺序即优先级**）

| # | 条件 | 结果 | `gated_by` | 代码入口 |
|---|---|---|---|---|
| 1 | `error_type == "系统繁忙"` | 原样返回，`llm_fail_count + 1` | — | `reflection_node` |
| 2 | `result` 以「执行崩溃 / 执行暂停」开头 | 转 `系统繁忙`，`llm_fail_count + 1` | — | `reflection_node` |
| 3 | `used_fallback` 且 字数 < 20 | `内容不合格` | `rule_fallback` | `reflection_node` |
| 4 | 已拆解 且 证据非空 且 子任务覆盖率 < 100% | `分解不合理` | `coverage_rule` | `reflection_node` |
| 5 | 复合主题未拆解 且 比较对象覆盖率 < 100% | `分解不合理` | `coverage_rule` | `reflection_node` |
| 6 | 裁判 LLM（GLM）输出 `error_type` | 进入确定性门控（7~11） | `llm` | `reflection_node` |
| 7 | 门控：证据 0 条 | **`降级通过`** | `gate` | `_apply_pass_gate` |
| 8 | 门控：`used_fallback=True`（本轮无检索证据，仅模型知识） | **`降级通过`** | `gate` | `_apply_pass_gate` |
| 9 | 门控：URL 不在来源清单（编造来源） | `内容不合格` | `gate` | `_apply_pass_gate` |
| 10 | 门控：字数 < `PASS_MIN_CHARS`（默认 120） | `内容不合格` | `gate` | `_apply_pass_gate` |
| 11 | 门控：无「【来源】」或可核验引用 < `PASS_MIN_CITED`（默认 1） | **`降级通过`** | `gate` | `_apply_pass_gate` |
| 12 | 裁判 LLM 抛异常 → 规则兜底（<20 字 / 7~11 命中 / 全部通过） | `内容不合格` / `降级通过` / **`通过`** | `rule_fallback`、`gate` | `rule_based_reflection` |
| 13 | 自由反思补检索：仍失败 / 成功（成功也过 7~11） | `降级通过` / **`通过`** 或 `降级通过`、`内容不合格` | `free_reflection` | `free_reflection_node` |

> 注意三点：
> 1. **第 7 条优先于第 8~11 条**：0 证据时即使答案短、即使编造 URL，也判 `降级通过` 而非 `内容不合格`（因为"没有资料"是根因，"写得好不好"已无意义）；第 8 条同理先于 9~11。
> 2. **第 4、5 条发生在 LLM 调用之前**，属于"规则先否决"，因此 `coverage_rule` 一旦命中，裁判 LLM 根本不参与 —— 这也是论文里"确定性规则 + 语义裁判"两级结构的位置所在。
> 3. **第 6、12、13 条是三条独立路径，7~11 是同一条否决链**（`_apply_pass_gate`）：改前只有第 6 条过门控，12/13 各自"直接判通过"，故 v1 的 `通过` 里混着"无引用"样本（见 4.1 P0-3 / P0-4）。判定表为 v2 语义，与 `data/runs/` 中的 v1 记录不可混表。

### 2.3 `_decide_next`（判定 → 重规划决策）

| 输入 `error_type` | 追加条件 | 输出结果 | 计数 / history | 代码 |
|---|---|---|---|---|
| `通过` / `降级通过` | — | 原样（不重规划） | **不递增** | L346-347 |
| `分解不合理` | `repeat_hit`（历史已有同类型） | `证据不足` → 自由反思 | `+1`，写 `[证据不足] …` | L360-366 |
| `分解不合理` | 首次出现 | `replan_scope = 全局` | `+1`，写 `[分解不合理] …` | L367-370 |
| `内容不合格` | 有证据（`no_evidence = False`） | `replan_scope = 局部` | `+1` | L372-378 |
| `检索失败` / `系统繁忙` / 其它 | — | `证据不足` → 自由反思 | `+1` | L380-382 |

> `_REPLAN_TYPES` 只登记 `分解不合理→全局`、`内容不合格→局部`；`检索失败`、`系统繁忙` 故意不登记，一律落到"证据不足 → 自由反思"，避免用同一条查询原地重试。

### 2.4 路由表（`main.py` L11-28，`route_after_reflection`）

| # | 条件 | 去向 |
|---|---|---|
| 1 | `通过` / **`降级通过`** | `END` |
| 2 | `系统繁忙` 且 `llm_fail_count >= 3` | `END`（熔断①：LLM 连续故障） |
| 3 | `系统繁忙` | `replan_local` → executor |
| 4 | `replan_count >= 3` | `END`（熔断②：重规划上限） |
| 5 | `证据不足` | `free_reflection` |
| 6 | `replan_scope == "全局"` | `replan_global` → planner |
| 7 | 其余 | `replan_local` → executor |

> 两个熔断互相独立：`llm_fail_count` 由**反思节点单点累加**、执行成功即清零；`replan_count` 由 `_decide_next` 累加、判 `通过` 时不递增。二者都不在 router 里自增（router 只读），避免出现"同一轮被加两次"导致提前熔断或死循环。

## 3. 现状实测（20 份 run 记录）

| 维度 | 分布 |
|---|---|
| `reflection.verdict` | 通过 **13** ／ 检索失败 **4** ／ 降级通过 **2** ／ 分解不合理 **1** |
| `reflection.gated_by` | `llm` **17** ／ `free_reflection` **2** ／ `rule_fallback` **1** |
| `replan_count` | 0 → **13** ／ 1 → **5** ／ 3 → **2** |

### 3.1 三个可直接写进论文的案例

1. **覆盖率规则误判 → 3 次重规划空转**
   `data/runs/比较Python和Java在并发编程与内存管理上-20261105-200614.json`
   `coverage.terms = ["Python", "Java在并发编程", "内存管理上"]`，后两项**永远不可能**字面命中 → `ratio = 0.333` → 判 `分解不合理` → `replan_count = 3` 空转到上限。
   根因：主题切分把"在…上的差异"当成了比较对象。**当前代码已修**（实测 `_clean_for_coverage("比较Python和Java在并发编程与内存管理上的差异")` → `Python和Java`），但**没有回归测试**（见 7.3 C7）。

2. **裁判 LLM 故障时"有证据即通过"**
   `data/runs/zzqxvbnm7418529630-20261105-193754.json`
   记录为 `verdict=通过, gated_by=rule_fallback, evidence_count=0`。
   按当前代码重放，实测已变为 `降级通过`（`gated_by=gate`）—— 该口子补了一半，但"有证据但答案零引用"仍判 `通过`（见 4.1 P0-3）。

3. **缺资料 → 降级收尾（正确示范样本）**
   `data/runs/比较Zig和Nim在内存安全与编译期检查上的差异-20261105-205742.json`
   0 证据 → 判 `检索失败` → 证据不足 → 自由反思补检索仍失败 → `降级通过`，`final_reason = 补检索仍失败，降级收尾`。
   这是"检索不到 ≠ 系统失败"的规范路径，可直接做论文插图。

### 3.2 必须解释的观察

20 次记录中 `gated_by=gate` 与 `coverage_rule` **各 0 次触发**。
即：**确定性门控从未真正拦下过任何样本**。这与 4.1 P0-1 的空洞（`has_source_line` 从未被使用）互为印证 —— 不是门控足够严，而是它**没有能力**发现"无来源"的样本；同时 `run_stats` 里也不记 `has_source_line` / `cited_count`，事后无法从数据里复查。故第 4、5 节的字段补全不是可选项。

## 4. 缺陷清单

### 4.1 P0 —— 判定语义漏洞（对应"通过判定太松"）

统一症状：**"答案可读"被当成了"答案可信"**。四处口子都通向同一个后果 —— 无来源/无引用的回答被判 `通过` 并计入合格样本。

| ID | 缺陷 | 现状证据 | 改法 | 验收用例 |
|---|---|---|---|---|
| **P0-1** | `has_source_line` 计算了但**从未被使用** | `utils.py` L59 定义；`nodes.py` L295-307 否决链只用 `evidence_nonempty` / `no_fabricated_url` / `len_ok`。**实测**：`content_gate(无【来源】无 URL, 有证据)` → `{len_ok: True, has_source_line: False, no_fabricated_url: True, evidence_nonempty: True}` → 全部通过 → 判 `通过` | 在 L300 前插入一档否决：`elif not gate["has_source_line"] or gate["cited_count"] == 0:` → `降级通过`（"可读但不可核验"） | C1、C2 |
| **P0-2** | "资料支撑度"无量化门槛 | 只有"证据非空"这一个二元条件，单主题 1 条证据即达标；无 `cited_count` / `citation_ratio` | `content_gate` 增 `cited_count`（命中来源清单的 URL 数，复用 `tools._url_key` 归一化）与 `citation_ratio = cited_count / min(len(sources), 3)`；新增门槛 `PASS_MIN_CITED`（默认 1） | C3 |
| **P0-3** | 规则兜底"有证据即通过" | `nodes.py` L333：`len ≥ 20 且 evidence_nonempty` → 直接 `通过`。**实测**：`rule_based_reflection(有证据但答案零引用)` → `{'error_type': '通过', 'gated_by': 'rule_fallback'}` | 兜底路径复用同一套门控（P0-1/P0-2 插入后自动生效），未过则 `降级通过`，`reason` 注明"规则兜底 + 无引用" | C4 ✅已复现 |
| **P0-4** | 自由反思"补到资料即通过"，**完全绕过门控** | `nodes.py` L399-400：`final_error_type = "降级通过" if used_fallback else "通过"`，不看字数、不看来源、不看引用 | 补检索成功后同样过 `content_gate`；未过 → `降级通过`，并在 `run_stats` 记 `pass_kind = "degraded"` | C5 |
| **P0-5** | 补检索用**同一条 query** → 命中同一份磁盘缓存 | `nodes.py` L388 `search_with_evidence(topic)`；缓存键 `sha1(provider|query|count|need_content)`，同参数必然同键 | 新增 `RETRY_QUERY_MODE`：`missing_term`（主题 + 未覆盖对象）/ `drop_lang`（去掉 `lang:zh`）/ `same`；把实际使用的 query 落到 `search.retry_query` | C6 |

**为什么 P0-1 与 P0-2 必须一起改**：只加 `has_source_line`，模型只要写一行 `【来源】` 就能蒙过；必须同时要求"引用数 ≥ `PASS_MIN_CITED` 且引用的 URL 能在来源清单里核验"，才是"资料支撑"而非"格式服从"。

**为什么 P0-3 / P0-4 是独立缺陷而不是 P0-1 的重复**：门控只覆盖"裁判 LLM 正常返回"这一条路径；裁判故障（P0-3）与自由反思收尾（P0-4）各自有一条`直接判通过`的短路，不经过门控。三条路径必须同时收口，否则实验里"降级率"会因为走了哪条路而抖动。

#### 4.1.1 落地情况（P0-1 ~ P0-5 已改，2026-11-05）

| ID | 实际改动 | 位置 |
|---|---|---|
| P0-1 + P0-2 | 新增三条路径共用的否决链 `_apply_pass_gate`：`证据为空` → `used_fallback` → `编造 URL` → `过短` → `无【来源】/引用数 < PASS_MIN_CITED`；`content_gate` 增 `cited_count`、`citation_ratio`（分母 `min(来源数, 3)`）、URL 归一化 + **路径边界前缀匹配**；`cited_loose` 单列记录"截断引用" | `utils.py` `_norm_url` / `_verified_kind` / `content_gate`；`agents/nodes.py` `_apply_pass_gate` |
| P0-3 | `rule_based_reflection` 改用同一条否决链，不再"≥20 字 + 有证据即通过"；未过时 `gated_by="gate"` | `agents/nodes.py` `rule_based_reflection` |
| P0-4 | `free_reflection` 补检索成功后同样过 `content_gate`，未过则 `降级通过`，并记 `pass_kind="degraded"` | `agents/nodes.py` `free_reflection_node` |
| P0-5 | `search_with_evidence(topic, query="")` 支持显式检索式，内存缓存键加入 `query`；`_build_retry_query` 按 `RETRY_QUERY_MODE` 改写，实际取式落 `run_stats.search.retry_query` / `retry_mode` | `tools.py`、`agents/nodes.py` |
| 记录字段 | `run_stats.reflection` 增 `pass_kind` / `has_source_line` / `cited_count` / `citation_ratio` / `len_ok` | `agents/nodes.py` `_reflection_stats`、`free_reflection_node._merge_reflection` |

> 与初稿的两处偏差：
> 1. 初稿写"复用 `tools._url_key`"，该函数**不存在**，实际在 `utils.py` 内实现 `_norm_url`（去锚点 `#`、去中英文尾随标点、小写、去尾斜杠）；
> 2. 初稿把 120 字阈值只在 P1-5 处理，实际 P0-2 就要读配置，故 `PASS_MIN_CHARS` 与 `PASS_MIN_CITED` 一并落在 `config.py` 第 1.2 节。

**离线实测（桩掉 LLM，不联网）**：

| 场景 | 改前 | 改后 |
|---|---|---|
| 裁判判「通过」，回答无【来源】无 URL | `通过` | `降级通过`（`无引用支撑`） |
| 裁判判「通过」，引用 1 条合法 URL | `通过` | `通过`（`pass_kind=strict`） |
| 裁判判「通过」，证据为空 | `降级通过` | `降级通过` |
| 裁判判「通过」，`used_fallback=True`（有历史证据残留） | `通过` | `降级通过`（`无资料兜底`） |
| 规则兜底 + 有证据 + 零引用 | `通过` | `降级通过` |
| 自由反思补检索成功 + 零引用 | `通过` | `降级通过` |

**实跑校验（2026-11-05，主题 `生物细胞的结构`，命中磁盘缓存；直接 `app.invoke`，不落 `data/runs/`）**：

| 版本 | 门控事实 | 最终判定 | 说明 |
|---|---|---|---|
| 首版（仅精确匹配） | `fabricated=[.../visitnodedetail]`、`cited_count=0` | `通过` → `内容不合格` → 局部重规划 1 次 | 模型把 `.../visitnodedetail?courseId=200901994&knowledgeId=116677997` 截断成 `.../visitnodedetail` 后引用 |
| 修复后（路径边界前缀匹配） | `fabricated=[]`、`cited_count=3`、`citation_ratio=1.0` | `通过`（`replan=0`） | 截断引用记入 `cited_loose`；只写域名根（`https://a.com`）仍判不可核验 |

> 教训：门控必须区分**"没引用"**与**"引用得省略"**。只用精确字符串比对会把真实可核验的回答判死，抬高 `内容不合格` 与 `replan_count` —— 把"严"变成"错"。凡是新增门槛，都要用真实样本反证一次再进论文表格。

## 6. 与论文主线的映射

检索层（DeepSeek 官方 Search API）降级为**基础设施**，只出现在"系统实现"一章；实验章围绕 **反思 → 重规划** 展开。

| 组 | 配置 | 要验证的命题 | 主要指标 |
|---|---|---|---|
| **E1** 基线 | `ENABLE_REFLECTION=False` | 无反思时的合格率下限 | 合格率、平均耗时 |
| **E2** 纯 LLM 反思 | `DISABLE_CONTENT_GATE=True`、关覆盖率/重复规则 | 语义裁判单独的误判率（假阳性 + 假阴性） | 误判率 |
| **E3** 本文方法 | 全默认 | 规则 + 语义两级是否降低误判 | 误判率、`pass_kind` 分布 |
| **E4** 消融·覆盖率 | `ENABLE_COVERAGE_RULE=False` | 复合主题"漏覆盖"能否被检出 | 覆盖不足检出率 |
| **E5** 消融·重复检测 | `ENABLE_REPEAT_RULE=False` | 重复错误是否导致空转（对照 3.1 案例①） | 空转轮次、重规划分布 |
| **E6** 故障注入 | `INJECT_LLM_FAIL=3` | 双熔断是否避免死循环 | 是否正常收敛、`llm_fail_count` |

**指标定义（论文口径，必须与 JSON 字段一一对应）**

- 合格率 = `verdict == 通过` 的样本数 / 总样本数（`降级通过` **不计入**分子）；
- 降级率 = `verdict == 降级通过` / 总数（缺资料 ≠ 失败，单独成列）；
- 错误检出率 = 人工标注为"不合格"且被系统判非 `通过` 的比例；
- 误判率 = `(降级通过被人工判为合格 + 通过被人工判为不合格) / 总数`；
- 纠正成功率 = 触发重规划后终态为 `通过` 的比例；
- 空转轮次 = `replan_count` 增长但终态未变为 `通过` 的轮次（用 `reflection_history` 复算）。

**成本**：6 组 × 3~5 主题 ≈ 20~30 次运行，单次 40~90 s（含裁判 GLM 过滤），约 **25~40 分钟**机器时间；若 `search_cache/` 命中，网络耗时可省但**裁判 LLM 不省**（见 README 耗时口径说明）。
