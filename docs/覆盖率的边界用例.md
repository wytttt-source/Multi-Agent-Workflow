# 覆盖率的边界用例（主题切分）

> 配套文档：`docs/反思判定状态机-改动清单.md` 的 P1-2 与用例 C7。
> 目的：把"主题该被切成哪几个比较对象"固化下来，防止 `_clean_for_coverage()` 改动后**静默退化**成误判。

## 1. 这条规则在判定链里的位置

`evidence_coverage(topic, evidence)` → `terms / hit / missing / ratio`
→ `reflection_node` 在调用裁判 LLM **之前**就能据此判 `分解不合理`（`gated_by=coverage_rule`）。
一旦 `terms` 切错，后果不是"判错一次"，而是**每轮都判错**：因为 `ratio` 恒定小于 1，重规划三次仍不达标 → 空转到 `replan_count=3` 上限。

## 2. 真实误判案例（已归档）

`data/runs/比较Python和Java在并发编程与内存管理上-20261105-200614.json`

```json
"coverage": {
  "terms": ["Python", "Java在并发编程", "内存管理上"],
  "hit": ["Python"],
  "missing": ["Java在并发编程", "内存管理上"],
  "ratio": 0.333,
  "count": 12
}
"verdict": "分解不合理", "gated_by": "llm", "replan_count": 3
```

问题：

1. `Java在并发编程`、`内存管理上` 是**短语碎片**，不可能作为字面量出现在证据文本里 → `missing` 永远非空；
2. `Java` 本身被吞进短语，导致"比较双方"里的第二方被判为未覆盖；
3. 于是"主题真的没被覆盖"与"切分错误"两种情形在数据上**无法区分**，规则失去判别力。

根因：`_clean_for_coverage()` 只剥离词尾的"差异/区别/对比/比较/异同"，没剥离中间插入的"在…上的"。

## 3. 当前实现（已修 + 有回归测试）

```python
_clean_for_coverage("比较Python和Java在并发编程与内存管理上的差异")
# -> "Python和Java"          ✅
_is_composite_topic("比较Python和Java在并发编程与内存管理上的差异")
# -> True
```

修复方式：在剥离"比较/对比"前缀与"差异/区别"后缀之后，再用 `在.+?的?(差异|区别|对比|比较|异同)$` 剥掉"在…上的"状语段，只留下比较对象。

## 4. 曾会切错的句式（P1-2 已修，保留为回归用例）

| 主题 | 修复前 terms（实测） | 修复后 terms（实测） | 原因与修法 |
|---|---|---|---|
| `Python和Java的并发性能` | `["Python", "Java的并发"]` | `["Python", "Java"]` | 后缀表只剥到"性能"，留下"的并发"；`_TERM_TAIL_RE` 补 `的?并发?性能` |
| `Rust与Go哪个更适合写后端` | `["Rust", "Go哪个更适合写后端"]` | `["Rust", "Go"]` | 缺疑问尾巴；新增 `_TERM_QUESTION_RE`（`哪个/哪些/如何/怎么/怎样/为什么/是什么/有哪些/谁/多少`） |
| `对比Kafka与RabbitMQ在吞吐上的表现` | `["Kafka", "RabbitMQ在吞吐上的表现"]` | `["Kafka", "RabbitMQ"]` | "在…上的表现"不在状语表内；`_clean_for_coverage` 与 `_TERM_ADVERBIAL_RE` 都已补 `表现/性能/优劣势/优缺点` |

> 另外命中判定改成**归一化比对**（`_norm_text`：去空白 + 小写），`Python` / `python` / `Py thon` 视为同一 term —— 之前大小写不一致会让 `ratio` 假性偏低。

## 5. 回归用例（已落地为 `tests/test_reflection_gate.py::CoverageTermTest`，纯函数、不联网）

| # | `topic` | 期望 `terms` |
|---|---|---|
| 1 | `比较Python和Java在并发编程与内存管理上的差异` | `["Python", "Java"]` |
| 2 | `量子计算和经典计算的区别` | `["量子计算", "经典计算"]` |
| 3 | `比较Rust和Go在内存安全与并发模型上的差异` | `["Rust", "Go"]` |
| 4 | `生物细胞的结构` | `["生物细胞"]`（实测；`_is_composite_topic=False`，故不触发"复合主题未拆解"分支） |
| 5 | `Python和Java的并发性能` | `["Python", "Java"]`（P1-2 修复后转绿） |

断言方式建议：只断言 `terms` 集合，不断言 `ratio`（`ratio` 依赖真实证据，且大小写/空格会影响命中，属于另一层归一化 —— 该层已由 `_norm_text` 处理，另有大小写专项用例）。

> **落地状态（2026-11-05，P1-2 完成后）**：第 1~5 条全部固化为 `tests/test_reflection_gate.py::CoverageTermTest` 的回归用例（`test_clean_for_coverage` / `test_composite_terms` / `test_non_composite_topic_terms_not_empty` / `test_p1_2_suffix_and_question_tails` / `test_hit_is_case_and_space_insensitive`），`python -m unittest discover -s tests -v` 全绿。真实跑批也验证过：E3 组 `比较Python和Java在并发编程与内存管理上的差异` 的 `coverage.terms=["Python","Java"]`、`ratio=1.0`、`replan=0`。

> 注意：非复合主题也会算出 `terms`（上表第 4 条），它只在"已经有子任务拆解"的分支里被使用；写测试时不要假设"非复合 ⇒ terms 为空"。
