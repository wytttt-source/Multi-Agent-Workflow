## 6. 局限（人工撰写，引用前必读）

1. **样本量 n=18**：只能看趋势与失败模式，不能给置信区间；每类陷阱 1 条，回答的是「这类错误有没有可能被抓到」，不是该类的错误率。
2. **真值是「定义真值」**：按 v2 口径（证据非空 / 字数 / URL 可核验 / 贴合主题）机械判定。其中 **S13（正文提及非来源链接）** 是*定义敏感项*：语义上回答可读，是 v2 定义对正文外链过度严厉造成的**规则假阳性**。若口径改为「只核验【来源】行」，S13 真值应改为「通过」，此时 R/L/C 三列各多一条「把合格判成不合格」的误伤 —— 指标完全由定义决定，这也是本实验把 S13 当讨论项、不当判决器优劣证据的原因。
3. **主观项**：**S14（偏题）** 的真值依赖人工判断「答非所问」，它是规则结构上无法处理的类别（偏题没有字面信号）；S05 的缺口则属于「字数统计口径」问题，改统计方式即可修，性质不同。
4. **配对设计的边界**：C 列回放的是 L 列那次调用的原始返回，而 L 列（E2 配置）的 prompt 不含覆盖率统计行；所以结论是「在**同一份**语义判断之上再叠门控能修掉什么」，不是「E3 完整 prompt 会带来什么」。
5. **temperature=0.1**：critic 仍有抖动，本文件 repeat=1；要彻底可复现需要把 `config.py` 的 `temperature` 降到 0（属独立的 A 项改动）。
6. **R 列不是随手写的正则**：它复用产线规则（覆盖率前置否决 + 门控 + 规则兜底），代表「LLM 完全不可用时的下限」，因此 R 列的表现应当被当作规则能力的**上界估计**。
7. **S11（兜底未声明）是构造项**：真实链路里 `used_fallback=True` 时证据通常也为空，会先命中「证据为空」分支；该条用于覆盖门控第 2 条分支，不代表线上分布。
8. **类别不平衡**：真值 5 合格 / 13 非合格，准确率会被非合格一侧主导，所以第 3 节同时给出精确率/召回率，结论段里的「误判率」才是本实验的主指标。

| S16 | 无证据但已声明 | 回答前置【声明】（基于模型知识），evidence/sources 置空、used_fallback=True | **降级通过** | 降级 ≠ 不合格；关键是它不能计入合格样本 |
| S17 | 真 URL + 编造 URL 混排 | 【来源】里同时给真实可核验 URL 和 fake.example.com | **内容不合格** | 一条真引用不能冲抵一条编造引用 |
| S18 | 正常合格（对照组） | E3 真实记录原样（含【来源】与 3 条可核验 URL） | **通过** | 对照组：三列都应该判通过 |
